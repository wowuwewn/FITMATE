# Fitmate V4 · Astra 디자인 통합

2026-11-06, Asia/Seoul. 대상은 기존 React + TypeScript + Vite 앱이다. 별도의 새 앱이나 iframe을 만들지 않았다. 배포는 수행하지 않았다.

## 확인한 자료

`prototypes/fitmate-v3/OPEN-FITMATE.html`, 개발용 HTML/CSS/JS, 이미지, `tokens.css`, `UX-REVIEW.md`, `INTEGRATION.md`가 모두 존재했다. 원본 PRD, JSON 두 개, 점수 정책, 현재 엔진·교체 후보 계산·저장·인트로·AI 요청 흐름을 함께 확인했다. 프로토타입의 이미지와 폰트는 기존 앱이 이미 갖고 있는 동일 자산을 재사용했다.

## 반영한 디자인

- 홈: 검색 아래 4개 바로가기, 메인 추천 1개와 보조 행 1개, 보충제/영양제 전환, 순번형 제품 목록과 담기/취소, 전체 카테고리 진입. 순번은 인기 순위가 아님을 표시했다.
- 탐색: 큰 이미지 카테고리를 44px 칩으로 줄이고 기존 9개 카테고리를 보존했다. 약물은 별도 탭이다. 제품 이름 17px, 설명 15px, 44px 담기 버튼, 취소와 뒤로가기를 제공한다.
- 조합함: 큰 SVG 점수와 요약을 흰 배경 위에 정리했다. 상세 버튼 아래의 최적화 분석 버튼이 기존 `onOptimize`로 직접 이동한다. 수량·선택 삭제·저장 상태는 원래 동작을 유지한다.
- 분석 상세: 점수 중복을 줄이고 현재 매칭된 성분 쌍·규칙·감점·미확인 조건을 먼저 노출했다. 복수 원인 선택, 실제 출처 바텀시트, 기존 전체 리포트의 제품·점수·주의·중복·한계·보류 규칙을 보존했다.
- 설명: 로컬 `RuleExplanation`은 현재 분석 객체의 점수/중복/누락만 설명한다. AI 생성이 아님을 표시하며 기존 AI 요청·응답·오류·출처·fingerprint 검증은 유지한다.
- 최적화: 반복되던 두 개의 전체 조합 카드를 전후 점수와 변경 제품을 담은 한 영역으로 정리했다. 유지되는 제품, 줄어든/추가된 원인, 남은 한계를 함께 보여준다.
- 공통: Pretendard, 화이트·쿨그레이·#55789B, 12px 버튼 모서리, 22px 좌우 여백, 15–16px 본문. 게이지 링·숫자는 같은 MotionValue를 사용하며 관계 연결·설명·교체·화면 전환은 모션 감소를 지원한다.

## 선택적으로 유지하거나 다르게 적용한 부분

- 프로토타입의 4개 간소화 필터만 복사하지 않고 기존 9개 카테고리와 빈 목록, 검색·정렬·이미지 필터를 유지했다.
- 프로토타입의 전용 localStorage 키, 처음부터 담겨 있는 DEMO 조합, 별도 저장 이름 스키마는 가져오지 않았다. 기존 키와 저장 형식, 빈 첫 조합, 중복 저장 방지와 복원을 유지한다.
- 데스크톱 설명용 사이드 패널과 독립 HTML의 앱 셸은 제품 화면에 넣지 않았다. 기존 430px 앱 프레임과 데스크톱 내부 스크롤을 유지했다.
- 탐색에서 반복 담기로 수량을 늘리는 기존 기능을 보존하고 별도 취소 버튼을 제공했다. 홈 목록은 선택 토글을 사용한다.
- 홈의 예시 적용은 기존 즉시 적용 흐름을 유지하며 선택 결과를 문구로 안내한다. 기존 인트로도 유지한다.
- 프로토타입의 AI 미연결 상태만 강제하지 않았다. 현재 앱의 실제 API 기능을 보존하고 서버 응답 종류에 따라 AI 생성/규칙 안내/연결 오류를 구분한다.
- 점수의 의학적 의미, 없는 시너지·성분·함량·가격·인기·후기는 추가하지 않았다.

`src/App.tsx`, `src/screens/Home.tsx`, `Explore.tsx`, `Cart.tsx`, `Result.tsx`, `Optimize.tsx`, `src/components/ScoreGauge.tsx`, `ProductImage.tsx`, `ProductDetails.tsx`, `AiExplanation.tsx`, 신규 `IngredientRelations.tsx`, `RuleExplanation.tsx`, `src/styles/v4.css`.

## 기능 및 데이터 경계

기존 `getReplacementCandidates`가 전후 `analyzeCart` 결과를 만든다. 미리보기에서 cart를 바꾸지 않으며, 적용 시 원본 카트와 비교 이력을 보존하고 새 결과 화면으로 이동한다. 변경 후 저장은 별도 선택이며 재진입·새로고침·복원 시 현재 엔진으로 다시 계산한다.

`Finding`의 제품 순서와 정렬된 성분 순서를 제품의 실제 성분 목록으로 대응해 SVG를 만든다. 감점은 엔진의 고유 원인 결과를 그대로 사용한다. 실제 매칭이 없으면 연결선을 만들지 않는다. 함량 null은 0으로 바꾸지 않는다.

## 남은 범위와 제한

- 실제 iOS Safari/Android 기기, VoiceOver/TalkBack과 OS 글꼴 확대·키보드 safe area 검수는 별도로 필요하다. 이번 반응형·터치는 Chrome/Playwright 기준이다.
- 실제 AI 제공자 연결은 새로 설정하지 않았다. 키 없는 응답과 오류, 모킹된 AI 응답 경로를 검수했다. 생성형 AI와 규칙 안내는 계속 구분한다.
- 제품 사진은 기존 목업이고 제품·성분 함량은 원본 DEMO 데이터의 한계를 그대로 갖는다. 실제 제품·임상 근거·함량 확보를 UI 통합 완료로 간주하지 않는다.
- 기존 Pretendard Variable 폰트 파일 약 2MB와 원본 PNG 자산 용량은 유지했다. 배포 성능 최적화는 별도 범위다.
- 알려진 주요 기능 실패나 가로 넘침은 남아 있지 않다. 기존 CSS 위에 V4 공통 스타일을 적용했으며, 후속 화면 확장 전에 사용하지 않는 V1/V2 CSS 정리는 별도 작업으로 할 수 있다.
