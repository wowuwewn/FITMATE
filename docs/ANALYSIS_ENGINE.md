# JSON 분석 엔진과 현재 지원 범위

## 데이터 결정

사용자가 이름 변경을 확인한 두 파일을 사용합니다. PRD와 JSON 원본은 수정하지 않았습니다.

| 파일 | 역할 |
| --- | --- |
| `src/data/cart_interactions_dataset.json` | 제품 17개, 등록 성분 ID, 성분 쌍 규칙 33개, `matching_contract`, 원본 시연 조합 6개 |
| `src/data/supplement_interactions_with_lactose_ko.json` | 조건부 규칙 12개를 읽고 미평가 이유·출처를 제공. 개인 응답/용량/제품 유당 정보 없이 자동 경고·감점하지 않음 |

후자는 기존 지침의 `supplement_interaction_rules.json`이 변경된 파일명입니다. 원래 파일명으로 복사하거나 임의의 세 번째 규칙 파일을 만들지 않았습니다.

## 구조

- `src/analysis/types.ts`: 제품 라벨/성분/규칙/분석 결과의 독립 타입. 함량은 `number | null`.
- `data.ts`: 두 원본 JSON을 연결하는 어댑터. 표시명이나 부분 문자열로 성분·약물 계열을 추정하지 않음.
- `conditions.ts`: 작은 조건 인터프리터. 결과를 충족/불충족/정보 부족/미지원으로 구분.
- `engine.ts`: 순수 함수 `analyzeCart(cart, dataset)`. React나 저장소에 의존하지 않음.
- `scoring.ts`: 고유 원인별 시연 지표 계산. [정책](./SCORING_POLICY.md).
- `optimization.ts`: 동일 분석 함수로 후보별 전후 결과와 새로운/줄어든 원인을 비교.
- `src/components/AnalysisDetails.tsx`: 제품·규칙·출처·감점·한계의 화면 표시만 담당.
- `src/lib/catalog.ts`, `presentation.ts`: 이미지/카테고리/표시명 및 demo persistence 정규화. 분석 로직을 포함하지 않음.

다른 카탈로그를 넣을 때 `AnalysisDataset`의 제품과 검증된 ingredient ID를 제공하면 엔진을 재사용할 수 있습니다. 새 데이터가 알려지지 않은 성분 ID를 쓰면 임의로 동의어를 만들지 않고 누락으로 보고합니다.

## 매칭

1. 제품 ID별 용기 수량을 정규화하고 서로 다른 제품을 수집합니다.
2. 모든 제품 쌍의 등록 성분 ID를 양방향 비교합니다.
3. `(rule_id, 정렬한 product_id 쌍)`으로 표시 중복을 제거합니다.
4. 모든 동일 성분의 중복 등록도 별도로 수집합니다. 해당 규칙이 없으면 정보 관찰만 제공하고 감점하지 않습니다.
5. 규칙 severity·원본 설명·HTTPS 출처·선택 상세 판정 상태를 반환합니다.
6. 제품 추가/삭제/수량 변경 때 App의 현재 cart로 다시 분석합니다. 수량은 용기 개수이며 일일 섭취량이 아닙니다.

`amount: null`은 0이 아닙니다. 함량이나 단위가 없으면 미확인으로 보존합니다. 실제 함량이 있더라도 현재는 섭취 횟수/시간이 없으므로 일일 총량·독성·과다 섭취를 계산하지 않습니다.

## 조건과 한계

| 조건 | 현재 동작 |
| --- | --- |
| `different_cart_products_contain_each_ingredient`, `symmetric: true` | 주 데이터의 성분 쌍 조회 지원 |
| 순수 `active_entities_present` | 등록 성분 존재 확인 |
| 순수 `distinct_products_same_ingredient` | 서로 다른 제품 수 확인. 용기 수량으로 대신하지 않음 |
| `window: local_day` | 실제 섭취일이 없어 미확인 |
| `oral_drug_separation` | 복용 시간·제형·라벨 정보가 없어 시간 충족 계산 안 함 |
| `ingredient_scope`, `qualifier.any` | 범위/섭취 변경 이력 확인 자료가 없어 추가 판정 보류 |
| 모르는 연산자, 추가 필수 조건, 비대칭 규칙, 미지원 severity/알림 유형 | 해당 필수 규칙 적용 제외와 이유 표시. 관련 필수 규칙을 평가하지 못하면 숫자 지표도 보류 |
| 보조 데이터 `co_use_check` 8개 | 개인 병용 확인 응답과 용량/계열 확인이 없어 적용 보류 |
| 보조 데이터 `personal_condition_check` 4개 | 개인 응답과 제품별 유당/제형이 없어 적용 보류. 병용금기로 바꾸지 않음 |

주 데이터의 `original_condition_for_optional_detailed_evaluation`은 계약상 선택 정밀 판정입니다. 이를 평가하지 못해도 성분 쌍 검토 경고를 없애지 않습니다. 반면 필수 `condition`을 알 수 없으면 충족으로 취급하지 않습니다.

`protein`을 WPC/WPI로, `potassium_supplement`를 `potassium`으로, 약 이름을 약물 계열로 자동 매핑하지 않습니다. 약물 경고는 별도 그룹으로 표시하고 임의 중단·용량 변경을 안내하지 않습니다. 개인 체질·유당불내증·알레르기 판정과 효능·시너지 추천은 구현하지 않았습니다.

## 교체 흐름

1. JSON에 있는 보충제 중 공통 등록 성분이 있고 성분 목록이 알려진 제품을 비교 후보로 제공합니다. 복용약/이미 담긴 제품/미등록 성분 후보는 제외합니다.
2. 현재/변경 구성을 **같은 `analyzeCart`**로 계산합니다. 고정 82/88 전환은 없습니다.
3. 원인 키로 줄어든/새로운 주의 관계를 표시합니다. 제품 ID만 바뀐 동일 원인을 해소로 세지 않습니다.
4. 확정 시 부모 App이 후보를 다시 검증하고 현재 cart에 반영합니다. 수량과 복용약을 유지합니다.
5. localStorage에 유지되는 새 cart로 재계산한 **분석 결과**에 바로 진입합니다. 변경 확인 문구, 현재 제품·수량, 지표, 주의사항을 함께 표시합니다.
6. 보관은 별도의 버튼입니다. 저장되는 것은 새 제품 구성이고, 이후 불러올 때 최신 규칙으로 다시 계산합니다.

예: P02(3용기)+M02 → P01(3용기)+M02에서 `R06`이 사라지고 시연 비교 지표 88→100. 이는 칼슘-약물 관계의 등록 매칭이 사라졌다는 뜻이며 안전성·효능 보장이 아닙니다. 반대로 P01+M01 → P03+M01이면 새 `R28`로 100→75이며 새 주의사항도 표시됩니다.

## 검사

`npm test`는 단위 테스트와 Playwright를 모두 실행합니다. 원본 demo_carts, 양방향/중복/다중 제품, null/미등록/미지원 조건, 일관성, 신규 주의사항, 교체 확정·보관·재진입·reload를 검증합니다. `npm run build`, `npm run lint`도 별도로 실행합니다.

배포 작업은 수행하지 않습니다. 검사에 사용하는 제품과 브라우저 저장소는 가상의 시연 데이터입니다.
